# Spec for #8: Add CI, run the checks on every pull request

## Goal

Add one GitHub Actions workflow that runs the three factory checks from `.pi/factory.json` on every
pull request and on every push to `main`:

| Job      | Command                                              |
|----------|------------------------------------------------------|
| `test`   | `just test` (`uv run pytest -q pipeline`)            |
| `ruff`   | `uv run ruff check pipeline`                         |
| `worker` | `cd worker && npm ci && npx wrangler deploy --dry-run` |

The workflow must be safe for fork PRs. It uses no secrets, triggers on `pull_request` (never
`pull_request_target`), pins every action to a full commit SHA, and grants only
`permissions: contents: read`. It never touches `data/` or the private dump. CONTRIBUTING.md
documents the checks.

## Non-goals

- `ruff format --check`. It is in the AGENTS.md lint line but not in the factory checks, and
  today it would reformat all four files in `pipeline/`. That belongs in its own issue.
- TypeScript type checking (`tsc`). `wrangler deploy --dry-run` bundles with esbuild and does not
  type check, even though AGENTS.md says "bundle/typecheck". That belongs in a separate issue.
- Deploying, publishing or any Cloudflare/R2 access. `just publish` is never run in CI.
- `just smoke` / `just sample` / `just dev`. They need a public-subset SQLite file, which CI does
  not have.
- Changing `.pi/factory.json`. Its three check commands stay byte-for-byte the same.
- New tests in `pipeline/test_build.py`. This change adds no pipeline logic.

## Design

No change to `pipeline/` logic, the export query, the public subset (ADR 3), URLs or redirects
(ADR 4), the build manifest (ADR 5), search (ADR 6) or the Worker (ADR 1). No ADR is contradicted
or needs updating. No `just` recipe changes.

### Finding that shapes the design: ruff is not a project dependency

`ruff` is not in `pyproject.toml`. On onclappc02, `uv run ruff check pipeline` only works because
`~/.local/bin/ruff` (0.8.4) is on PATH. A clean CI runner would fail with "ruff: command not
found". Current ruff also flags code that 0.8.4 passes. Verified with
`uv run --with ruff ruff check --isolated pipeline`: ruff 0.17.2 and 0.16.10 both report

```
FURB167 regex-flag-alias  pipeline/build.py:34       re.I -> re.IGNORECASE
FURB167 regex-flag-alias  pipeline/media_paths.py:11 re.I -> re.IGNORECASE
```

The fix: make ruff a locked dev dependency, so the factory, local runs and CI all use the same
version from `uv.lock`, and fix the two findings (`re.I` and `re.IGNORECASE` are the same flag
object, so behavior does not change).

### Files

1. **`pyproject.toml`**: add `ruff` to the existing `dev` dependency group by running
   `uv add --dev ruff`. Expected result: `dev = ["pytest", "ruff>=0.17.2"]` (whatever lower bound
   `uv add` writes for the current release). `uv sync` installs the `dev` group by default, so
   `uv run ruff` then resolves to `.venv/bin/ruff`.
2. **`uv.lock`**: regenerated by that `uv add`. Commit it. CI runs `uv sync --locked`.
3. **`pipeline/build.py` line 34** and **`pipeline/media_paths.py` line 11**: replace `re.I` with
   `re.IGNORECASE`. Change nothing else on those lines. Reformatting is a non-goal.
4. **`.github/workflows/ci.yml`** (new). Use exactly this content:

   ```yaml
   name: CI

   on:
     pull_request:
     push:
       branches: [main]

   # Fork-safe: no secrets, read-only token, plain pull_request trigger.
   permissions:
     contents: read

   jobs:
     test:
       runs-on: ubuntu-24.04
       timeout-minutes: 10
       steps:
         - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
           with:
             persist-credentials: false
         - uses: astral-sh/setup-uv@07a047e608db84b3d8c06cd9a7c7dcc9c355c18e # v10.3.2
           with:
             python-version: "3.11"
         - uses: extractions/setup-just@53165ef7e734c5c07cb06b3c8e7b647c5aa16db3 # v4.0.0
         - run: uv sync --locked
         - run: just test

     ruff:
       runs-on: ubuntu-24.04
       timeout-minutes: 10
       steps:
         - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
           with:
             persist-credentials: false
         - uses: astral-sh/setup-uv@07a047e608db84b3d8c06cd9a7c7dcc9c355c18e # v10.3.2
           with:
             python-version: "3.11"
         - run: uv sync --locked
         - run: uv run ruff check pipeline

     worker:
       runs-on: ubuntu-24.04
       timeout-minutes: 10
       env:
         WRANGLER_SEND_METRICS: "false"
       steps:
         - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
           with:
             persist-credentials: false
         - uses: actions/setup-node@949feb2413d6458794dcd2491c4babbbce0c15c1 # v7.1.0
           with:
             node-version: "22"
             cache: npm
             cache-dependency-path: worker/package-lock.json
         - run: npm ci
           working-directory: worker
         - run: npx wrangler deploy --dry-run
           working-directory: worker
   ```

   Choices, all verified on 2026-10-24:
   - **Action pins** are the commit SHAs of each action's latest release, resolved with
     `gh api repos/<owner>/<repo>/commits/<tag>`: checkout v7.0.1, setup-uv v10.3.2, setup-node
     v7.1.0, setup-just v4.0.0. The input names (`persist-credentials`, `python-version`,
     `node-version`, `cache`, `cache-dependency-path`) were read from each action's `action.yml`
     at that SHA. `extractions/setup-just` needs no inputs and installs the latest `just`.
   - **Python 3.11** is the `requires-python` floor. `uv run --python 3.11 pytest -q pipeline`
     passes, and every `pipeline/*.py` and `docs/figures/*.py` file parses with
     `feature_version=(3, 11)`.
   - **Node 22**: `wrangler@4.152.0` in `worker/package-lock.json` declares
     `"engines": {"node": ">=22.0.0"}`.
   - **Credentials**: `wrangler deploy --dry-run` needs no Cloudflare credentials. Run locally
     with `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID` unset, it prints the bindings and
     `--dry-run: exiting now.` with exit 0. Without `--outdir` it writes no files.
   - **No `data/` access**: `data/` is gitignored, so a checkout contains none of it, and no step
     reads it. `persist-credentials: false` keeps the token out of `.git/config`.
   - **Three jobs** named after the factory checks, so a PR shows which check failed.

5. **`CONTRIBUTING.md`**: under "Pull requests", replace the bullet
   "Python style: `uvx ruff check` and `uvx ruff format`. TypeScript: match the surrounding code."
   with these two bullets:

   ```markdown
   - CI (`.github/workflows/ci.yml`) runs three checks on every pull request and push to `main`;
     run them locally before pushing:
     - `just test`: Python tests, which use small synthetic fixtures and never the real dump;
     - `uv run ruff check pipeline`: lint (ruff is pinned in `uv.lock`);
     - `cd worker && npm ci && npx wrangler deploy --dry-run`: bundles the Worker without deploying.

     CI uses no secrets and has no access to the dump or `data/`, so it runs the same way on
     pull requests from forks.
   - Python formatting: `uv run ruff format pipeline`. TypeScript: match the surrounding code.
   ```

## Acceptance criteria

- [ ] `.github/workflows/ci.yml` exists with the content above. Triggers are `pull_request` and
      `push` to `main`. `pull_request_target` appears nowhere.
- [ ] Top-level `permissions:` is exactly `contents: read`. No job widens it.
- [ ] Every `uses:` points to a 40-hex-character SHA with a version comment.
- [ ] The workflow references no `secrets.` and no `data/` path.
- [ ] `pyproject.toml` lists `ruff` in the `dev` group, and `uv.lock` is updated to match:
      `uv sync --locked` succeeds.
- [ ] `uv run ruff check --isolated pipeline` passes, with `re.IGNORECASE` at `build.py:34` and
      `media_paths.py:11`. The `--isolated` flag rules out user-level config.
- [ ] `just test` passes, and passes under Python 3.11.
- [ ] `cd worker && npm ci && npx wrangler deploy --dry-run` exits 0.
- [ ] CONTRIBUTING.md lists the three checks and says CI is fork-safe and secret-free.
- [ ] `.pi/factory.json` is unchanged.
- [ ] After the PR is opened, all three CI jobs (`test`, `ruff`, `worker`) are green on it.

## Test plan

This change adds no pipeline logic, so it adds no new pytest tests (see Non-goals). The existing
test (`pipeline/test_build.py::test_rewrite_links`) is pure-string and uses no data. The
implementer runs these and reports the output:

```sh
uv sync --locked
just test
UV_PROJECT_ENVIRONMENT=$TMPDIR/bsa8-py311 uv run --python 3.11 pytest -q pipeline
uv run ruff check --isolated pipeline
uv run ruff --version                      # must be the uv.lock version, not 0.8.4
(cd worker && npm ci && env -u CLOUDFLARE_API_TOKEN -u CLOUDFLARE_ACCOUNT_ID npx wrangler deploy --dry-run)
grep -n 'pull_request_target\|secrets\.\|data/' .github/workflows/ci.yml   # expect no matches
grep -nE 'uses: [^@]+@[0-9a-f]{40} # v' .github/workflows/ci.yml          # expect 7 matches
git diff --exit-code main -- .pi/factory.json
```

Optional YAML syntax check:
`uv run --with pyyaml python -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))" .github/workflows/ci.yml`.
The final proof is the green run on the PR itself.

## Risks

- **Unpinned `just`**: `extractions/setup-just` installs the latest `just`. The justfile uses only
  long-stable features, so the risk is low. If it ever breaks, pin with `with: just-version: ...`.
- **Ruff upgrades**: a later `uv lock --upgrade` can bring new default rules that turn CI red.
  That is intended: the version only moves through a reviewed lockfile change.
- **Machine-wide ruff 0.8.4**: after this change `uv run ruff` uses the locked version. Anyone
  calling bare `ruff` or `uvx ruff` (as AGENTS.md's Commands section still does) may see
  different results. AGENTS.md is left alone here. Aligning it is a one-line follow-up if wanted.
- **Workflow file permissions**: pushing `.github/workflows/*` needs a token with the `workflow`
  scope. If the PR push is rejected for that reason, a person must push the branch.
- **Network in CI install steps**: `uv sync` downloads Python, PyPI wheels (including the
  `pagefind_bin` wheel) and npm packages. Tests themselves use no network.
