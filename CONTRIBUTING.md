# Contributing

Thanks for helping keep the Bioconductor support archive useful. By taking part you agree to follow
the [Code of Conduct](CODE_OF_CONDUCT.md).

## Reporting problems

[Open an issue](https://github.com/seandavi/bioc-support-archive/issues) for anything that looks
wrong in the archive, such as:

- a thread, answer or image that is missing or renders badly;
- an old `support.bioconductor.org` link that no longer resolves;
- search results that miss something you know is there;
- accessibility or mobile layout problems.

Include the URL, what you expected and what you saw. For content you think should be removed
(for example, personal information in a post), open an issue without repeating the information,
or contact [@seandavi](https://github.com/seandavi) directly if even the issue would expose it.

## Working on the code

The pipeline's input is a database dump of the original site, which contains private data and is
not distributed. You can still work on most of the project without it:

- **Worker** (`worker/src/index.ts`): routing, redirects and caching. Any directory of HTML files
  loaded with `just sync-local <dir> <state-dir>` is enough to test it.
- **Templates and styling** (`pipeline/build.py`, `pipeline/style.css`): if you need sample
  data, ask in an issue. With a public-subset SQLite file, `just sample` rebuilds in seconds.
- **Docs and figures** (`docs/`): figures are generated by stdlib Python scripts in
  `docs/figures/`. Edit the script and run `just figures`; don't edit the SVG by hand.

Setup:

```sh
uv sync                      # Python dependencies (DuckDB, Pagefind)
(cd worker && npm install)   # Worker dependencies (Hono, wrangler)
just test                    # Python tests
```

## Pull requests

- Keep each pull request to one change, and describe what you checked (for example `just smoke`
  output or a screenshot of the page you changed).
- Add or update a test in `pipeline/test_build.py` when you change logic, such as link rewriting
  or filtering.
- Never commit anything from `data/`, including dumps, exports, builds and images.
- Changes to **what gets published** (the filters in `pipeline/export.py`) or to URL behavior
  need an update to the matching ADR in `docs/adr/`. Changes to the public subset get extra review,
  because they can expose data that was never public.
- Python style: `uvx ruff check` and `uvx ruff format`. TypeScript: match the surrounding code.
